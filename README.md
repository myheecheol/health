# 🏋️ Fitness RPG

근력 운동(A/B 루틴)과 러닝을 하나의 게임 루프로 묶은 개인 운동 기록 웹앱입니다.

> **기록 → 경험치 → 레벨 → 업적 → 보상 → 성취감 → 다음 운동**

현재 **1단계 MVP**까지 구현되어 있습니다.

---

## 앱 열기

**https://myheecheol.github.io/health/**

휴대폰 브라우저에서 위 주소를 열고 **홈 화면에 추가**하면 앱처럼 전체화면으로 실행됩니다.
이 브랜치에 푸시할 때마다 GitHub Actions가 자동으로 다시 배포합니다.

```bash
npm install
```

## 데이터 보관 방식

기록이 사라지지 않게 하는 것을 최우선으로 설계했습니다.

```
세트 완료 버튼
   ↓  (동기, 즉시)
localStorage 기록          ← 정본. 여기 쓰이면 그 순간 안전합니다.
   ↓  (비동기 큐)
Firestore 업로드           ← 서버가 성공을 응답해야 큐에서 지웁니다.
   ↓  (실패 시)
재시도 큐에 보존           ← 지수 백오프로 재시도, 앱을 껐다 켜도 유지
```

**5중 방어**

1. **매 세트 즉시 저장** — 저장을 `useEffect`에 맡기지 않고 상태 변경과 같은 시점에 동기로 씁니다.
2. **직전 스냅샷 보존** — 쓰기 전에 이전 값을 `:prev` 슬롯에 남겨, 저장이 깨져도 한 세대 전으로 복구합니다.
3. **되읽기 검증** — 쓴 직후 다시 읽어 대조하고, 실패하면 화면 상단에 경고를 띄웁니다(조용한 실패 방지).
4. **파괴적 삭제 없음** — 삭제는 `deletedAt` 표시만 하고 데이터는 남깁니다.
5. **백업 파일** — 설정 화면에서 전체 기록을 JSON으로 내려받고, 다시 합칠 수 있습니다.

진행 중인 운동은 타이머를 "카운트 변수"가 아니라 **`startTime` 기준 실시간 계산**으로 다루기 때문에,
새로고침·앱 종료·백그라운드 전환 후에도 경과 시간과 진행 위치가 정확히 복구됩니다.

### 동기화 상태 표시

화면 우측 상단 배지가 항상 현재 상태를 보여줍니다.

| 배지 | 의미 |
|---|---|
| ✅ 저장됨 | 클라우드까지 반영 완료 |
| ⏳ n건 대기 | 업로드 대기 중 (기록은 이미 로컬에 안전) |
| ⚠️ n건 대기 | 업로드 실패, 자동 재시도 중 |
| 💾 로컬 저장 | Firebase 미설정 — 이 기기에만 저장 |

## Firebase 연결

연결하면 기록이 클라우드에 저장되어 **휴대폰과 컴퓨터에서 같은 기록**을 보게 되고,
브라우저 데이터를 지워도 기록이 남습니다.
연결하지 않아도 앱은 정상 동작합니다 (그 기기에만 저장됨).

### 1단계 — Firebase에서 프로젝트 만들기

1. [Firebase 콘솔](https://console.firebase.google.com) 접속 → **프로젝트 추가**
2. 이름은 아무거나 (예: `fitness-rpg`). Google 애널리틱스는 꺼도 됩니다.

### 2단계 — 익명 로그인 켜기

왼쪽 메뉴 **빌드 → Authentication → 시작하기 →** `Sign-in method` 탭
→ **익명(Anonymous)** 선택 → **사용 설정** 켜고 저장.

기기마다 이름 없는 계정이 하나 생기고, 그 계정에만 자기 기록이 붙습니다.
아이디·비밀번호를 만들 필요가 없습니다.

### 3단계 — 데이터베이스 만들기

왼쪽 메뉴 **빌드 → Firestore Database → 데이터베이스 만들기**
→ 위치는 `asia-northeast3 (서울)` → 프로덕션 모드로 시작.

만들어지면 **규칙** 탭으로 가서, 이 저장소의 [`firestore.rules`](firestore.rules)
파일 내용을 통째로 복사해 붙여넣고 **게시**를 누르세요.
이게 있어야 남이 내 기록을 못 읽습니다.

### 4단계 — 설정값 6개 받아오기

왼쪽 위 **⚙️ 톱니바퀴 → 프로젝트 설정** → 아래로 스크롤해서 **내 앱** 항목
→ **`</>` (웹) 아이콘** 클릭 → 앱 닉네임 아무거나 입력 → **앱 등록**.

그러면 이런 화면이 나옵니다.

```js
const firebaseConfig = {
  apiKey: "AIzaSyC7x...",
  authDomain: "fitness-rpg-1234.firebaseapp.com",
  projectId: "fitness-rpg-1234",
  storageBucket: "fitness-rpg-1234.appspot.com",
  messagingSenderId: "123456789012",
  appId: "1:123456789012:web:abc123def456"
};
```

**여기 있는 6개 값이 필요한 전부입니다.** 이 화면은 나중에도
프로젝트 설정 → 내 앱에서 다시 볼 수 있습니다.

> `apiKey`라는 이름 때문에 비밀번호처럼 보이지만, 아닙니다.
> 이 값들은 웹앱이라면 누구나 볼 수 있게 코드에 포함되는 **주소표 같은 것**입니다.
> 실제 보안은 3단계에서 붙여넣은 규칙과 익명 로그인이 담당합니다.

### 5단계 — 값을 어디에 넣나

**두 군데**에 넣어야 합니다. 목적이 다릅니다.

#### (가) 배포된 앱 — `myheecheol.github.io/health`

이쪽이 실제로 쓰는 앱입니다. GitHub 저장소에 넣습니다.

저장소 → **Settings** → 왼쪽 **Secrets and variables → Actions**
→ **Variables** 탭 → **New repository variable** 을 6번 눌러 하나씩 추가합니다.

| Name (그대로 입력) | Value |
|---|---|
| `VITE_FIREBASE_API_KEY` | `apiKey` 값 |
| `VITE_FIREBASE_AUTH_DOMAIN` | `authDomain` 값 |
| `VITE_FIREBASE_PROJECT_ID` | `projectId` 값 |
| `VITE_FIREBASE_STORAGE_BUCKET` | `storageBucket` 값 |
| `VITE_FIREBASE_MESSAGING_SENDER_ID` | `messagingSenderId` 값 |
| `VITE_FIREBASE_APP_ID` | `appId` 값 |

따옴표는 빼고 값만 넣으세요. 다 넣었으면 저장소에 아무 커밋이나 푸시하거나,
**Actions** 탭 → `Deploy to GitHub Pages` → **Run workflow** 로 다시 배포하면 적용됩니다.

적용됐는지 확인하려면 앱 오른쪽 위 배지를 보세요.
`💾 로컬 저장` 이 `✅ 저장됨` 으로 바뀌면 성공입니다.

#### (나) 내 컴퓨터에서 개발할 때 (선택)

`npm run dev` 로 직접 돌려볼 때만 필요합니다. 안 해도 됩니다.

```bash
cp .env.example .env
```

만들어진 `.env` 파일을 열어 `=` 뒤에 값을 붙여넣습니다.

```
VITE_FIREBASE_API_KEY=AIzaSyC7x...
VITE_FIREBASE_PROJECT_ID=fitness-rpg-1234
```

`.env` 는 `.gitignore` 에 있어서 깃허브에 올라가지 않습니다.

---

값이 비어 있으면 앱은 로컬 저장소만 사용하며 정상 동작합니다.
Firebase SDK는 별도 청크로 분리되어 있어, 설정하지 않으면 내려받지도 않습니다.

### 웨이트와 러닝을 섞이지 않게 하는 3중 장치

1. **타입** — `WorkoutSession`이 판별 유니온이라, 러닝 세션에서 `sets`를 읽으면 빌드가 실패합니다.
2. **집계** — 볼륨은 근력만, 거리는 러닝만 순회합니다. 공통 집계는 횟수·시간·스트릭·XP 넷뿐입니다.
3. **검증** — 거리는 `validateDistanceKm`를 통과한 `number`만 저장됩니다. 문자열이 들어갈 경로가 없습니다.

### 휴식 종료 알림이 오는 조건

웹앱은 **앱을 열어둔 동안에만** 알림을 보낼 수 있습니다.
그리고 화면이 꺼지면 브라우저가 타이머를 멈춰, 60초 뒤에 울려야 할 알림이
폰을 다시 켤 때까지 오지 않습니다.

그래서 운동 중에는 **화면이 꺼지지 않도록 붙잡습니다** (Screen Wake Lock).
설정에서 끌 수 있고, 지원하지 않는 기기에서는 조용히 넘어갑니다.

| 상황 | 알림 |
|---|---|
| 앱을 보고 있음 | ✅ 소리 · 진동 · 배너 |
| 화면 켠 채 다른 앱 사용 | ✅ 배너 (알림 권한 필요) |
| 화면을 끔 | ✅ 화면 켜두기가 켜져 있으면 안 꺼짐 |
| 앱을 완전히 닫음 | ❌ 불가 — 보낼 서버가 없습니다 |

마지막 줄을 해결하려면 Web Push와 푸시를 보낼 서버가 필요합니다.

### 운동 중 종목 이동

헬스장에서 기구가 차 있으면 순서를 바꿔야 하므로, 진행 화면 위쪽 띠에서
아무 종목이나 눌러 바로 이동할 수 있습니다. 각 칩에 `2 / 4` 처럼 진행도가 보이고,
끝낸 종목은 `✓` 로 표시됩니다.

한 종목의 세트를 다 채우면 다음 미완료 종목으로 자동으로 넘어갑니다.
이때 **뒤쪽부터 찾고 없으면 앞으로 한 바퀴 돕니다** — 사용자가 고른 순서를 존중해,
일부러 건너뛴 종목으로 되돌아가 붙잡지 않기 위해서입니다.

끝낸 종목을 다시 골라 세트를 더 할 수도 있습니다.

### A/B 순서 규칙

`getNextStrengthRoutine()` 한 곳에서만 결정합니다.
정렬 이전에 러닝을 걸러내므로, **러닝을 몇 번 하든 A/B 순서는 바뀌지 않습니다.**

```
A → 러닝 6km → 러닝 8km  →  다음은 B
B → 러닝 8.5km           →  다음은 A
러닝만 여러 번            →  다음은 A (근력 기록 없음)
```

이 규칙은 `src/domain/progression.test.ts`에 10건의 테스트로 고정되어 있습니다.

## 그래프

차트 라이브러리를 쓰지 않고 SVG로 직접 그립니다 (`src/components/Chart.tsx`).

화면의 UI 색(`--strength` / `--running`)을 그대로 마크에 쓰면 어두운 배경에서
너무 밝아 읽기 어려워, 같은 계열의 어두운 단계를 `--chart-*` 로 따로 두었습니다.
색약 구분(ΔE 10.0)과 배경 대비(3:1 이상)를 검증한 값입니다.

모든 그래프에는 **표 보기**가 함께 있습니다 — 값이 툴팁에만 갇히지 않도록.

## 설정값 바꾸기

게임 밸런스는 전부 `src/config/gameConfig.ts`에 있습니다.

```ts
XP_RULES.RUNNING_PER_KM   // 러닝 1km당 XP (기본 30)
XP_RULES.SET_COMPLETE     // 세트 완료 XP (기본 5)
POINT_RATE                // 포인트 = XP × 이 값 (기본 0.5)
LEVEL_CURVE               // 레벨 곡선 (기본 600 시작, 레벨마다 +300)
STREAK_MAX_GAP_DAYS       // 이 일수를 넘겨 쉬면 연속 기록 초기화 (기본 3)
RUNNING_LIMITS            // 거리 입력 허용 범위
```

### 보상 밸런스

수치는 **"운동 2~3번이면 약속(300P) 한 번"** 이 되도록 맞췄습니다.

| 운동 | 획득 XP | 획득 포인트 |
|---|---|---|
| A 루틴 완주 (26세트) | 370 | 185P |
| B 루틴 완주 (25세트) | 360 | 180P |
| 러닝 5km | 150 | 75P |
| 러닝 6.8km | 204 | 102P |
| 러닝 10km | 300 | 150P |

| 보상 | 가격 | 필요한 운동 |
|---|---|---|
| 🍕 일반식 | 100P | 1번 |
| 🎬 영화 | 200P | 2번 |
| 🍺 약속가기 | 300P | **2~3번** |
| 🛌 늦잠 쿠폰 | 300P | 2~3번 |
| 🎮 놀러가기 | 500P | 3~4번 |

보상 가격은 앱 안에서 직접 바꿀 수 있습니다. 가격을 바꾸면 이 균형도 함께 다시 보세요.
`src/domain/xp.test.ts` 가 이 관계를 테스트로 지키고 있습니다.

운동 종목을 바꾸려면 `src/config/routines.ts`의 배열만 수정하면 됩니다.
`id`는 과거 기록과 연결되므로 한번 정한 뒤에는 바꾸지 마세요.

## 배포

`.github/workflows/deploy.yml` 이 푸시마다 타입 검사 → 테스트 → 빌드 →
GitHub Pages 배포를 수행합니다. 테스트가 실패하면 배포되지 않습니다.

주소가 `/health/` 하위이므로 `vite.config.ts` 의 `base` 를 그에 맞춰 두었습니다.
다른 곳에 올릴 때는 `BASE_PATH=/ npm run build` 처럼 바꿀 수 있습니다.
